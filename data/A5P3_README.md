# A5P3 - Readiness-aware multi-region provisioning under rate limits

**Track:** Track 7  
**Application:** Provisioning for green multi-region smart-city platforms

> This dataset is synthetic, generated by gen_author5.py with seed 2079. It must be described as synthetic in any publication.

## Simulated scenario

Smart-city platforms (traffic sensors, lighting, air quality, parking, transit events) are provisioned across six regions with different API rate limits and grid carbon intensity. Each row is one resource provisioning task inside an IaC plan: rate-limit pressure, prerequisite readiness, backoff policy and polling interval determine throttling, time-to-ready and failures. A readiness-aware, carbon-aware scheduler should order and pace tasks to minimise makespan, throttling and carbon.

## How it was generated

- Demand ratio = (api_calls x concurrent/60 + other tenants) / rate limit; throttle errors ~ Poisson(8 x (demand-0.8)^1.5 x backoff multiplier x (1.3 - bucket fill)).
- time_to_ready = type ready time x regional perf x LogNormal(0,0.3) + throttles x backoff penalty + poll interval/2 + 120 s x unready prerequisites + overload term.
- Failure ~ Bernoulli(sigmoid(-4.2 + throttles(no backoff) + unready prerequisites + slow types + regional effect)); failed tasks take 1.2-2.5x longer.
- Carbon intensity has a regional base and a solar dip by hour.
- Noise: 5% Gaussian, ~0.7% outliers (time_to_ready, tenant load), 1-3% missing (tenant load, bucket fill, carbon).

## Target / label columns

- `time_to_ready_s` (regression).
- `provisioning_failed` (binary, rare).
- `throttle_errors` (count, auxiliary).

## Suggested experiments

1. Readiness-time prediction: regress log time_to_ready_s (R2, MAE); baseline = typical_ready_time_s.
2. Throttle-risk model: predict throttle_errors > 0 and use it in a rate-limit-aware scheduler; simulate plan makespan vs FIFO and max-concurrency baselines.
3. Failure prediction: F1/PR-AUC for provisioning_failed.
4. Green scheduling: schedule deferrable resources toward low-carbon regions/hours; report carbon (gCO2 x estimated energy) vs makespan Pareto front.

## Notes

- Realism noise: ~5% Gaussian measurement noise on numeric signals, 1-3% missing values in a few columns, ~0.5-1% gross outliers in a few columns. Label/target columns are never noised by the measurement-noise step (they carry their own stochasticity).
- All IDs, sites, regions and assets are synthetic; no real people, companies, IPs or CVEs.
- The dataset contains inputs and ground truth only - no results of any proposed method.
